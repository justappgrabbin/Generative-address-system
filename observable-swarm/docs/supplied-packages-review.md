## Three additional packages

Downloaded and unpacked separately; targeted inspection, not a complete audit.

- **Synthia v0.5.1 Automata Ingestion Execution Patch**: 16 files. Artifact
  normalization, primitive reduction, execution receipts and browser persistence.
  Its five execution fields are shared/knowledge/causal/dependency/stateSpace;
  they must not be substituted for Movement/Evolution/Being/Design/Space.
  This is an overlay requiring an earlier checkpoint, not a standalone system.
- **Kimi Agent Automata State Space Merge (4)**: 149 files, including the
  16-tool collection, source ledger, Boolean ATO engine and string analogy tier.
  `src/engine/boolean-ato.js` actually implements vector XOR/XNOR, analogy
  completion, involution checks, feature-space lookup, aligned tree transforms,
  plan retargeting and operator hierarchies. After reviewing its dependency-free
  code, ran the paper's iconographic example: A=111110, B=010001, C=100101;
  XNOR relation=010000 and D=001010. All 8192 six-bit pair involution checks
  (4096 pairs in each mode) passed, as did a plan-retargeting endpoint check.
  These are arithmetic checks, not evidence of semantic fidelity or learned
  computation. Tree transform requires matching tree shape. The 16 tools are
  separately authored algorithms, not 16 emergent learned formations.
  Tool 16 Morph-MIR analyzes source text and distinguishes byte-equal recovery
  from a generated runtime; its inspected analyzer uses regex/keyword extraction.
- **Synthia Universal Execution Spine v0.2.0**: 33 files including donor archives.
  Serializable Boolean predicate IR, state machine, DAG execution, runtime
  adapters and explicit verification boundaries are relevant foundations.
  `realizers.mjs` also permits registered named capabilities and external
  adapters; these execution paths are not proof of swarm-carried computation.
  Keep foundational scheduling, serialization and OS contact distinct from
  supplied task functions. Fine-index/address assumptions need reconciliation
  with user/source rules before adoption.

No archive was merged into the native substrate. The ATO arithmetic is the
strongest verified new match to Klein's source mechanism in this inspection.
Character-quality image reconstruction, rigging and learned walking remain
unproven; package titles do not establish those capabilities. Nested donor
archives have not been exhaustively reviewed.

These are useful examples/oracles and contract specifications for learning.

Important conflicts: the inspected state_space_core maps King Wen to Design
and assigns unconfirmed reversal/complement defaults to other dimensions.
The current conversation explicitly assigns King Wen to Movement, Mawangdui to
Evolution and Fu Xi to Being; current user instructions take precedence. The
Mawangdui implementation says it approximates within-family ordering rather than
transcribing the manuscript sequence. Integrated factory `gateBits(gate)` uses
`gate-1`, which is not a canonical King Wen-to-binary conversion. Do not import
these mappings unquestioned. Five separate stored layers also do not establish
the user's unified five-dimensional substrate.

Also inspected resonance-neural-net's canonical orchestrator/meta-orchestrator:
contains routing/assembly references, but default remote API and heuristic/random
mappings are incompatible with current backend-free and source-grounding rules.
Exact user term 'model maker' and the fourth maker component remain unidentified.

Proposed learning contract: preserve an existing tool as an external example
provider/oracle, expose inputs and outcomes to a small formation, forbid calls
to that tool during held-out execution, verify execution traces and relevant
connection ablation, persist learned state, then test composition on unseen
combinations. Framework-wide universality is not established by names or passing
one task; scheduling, conditional control, writable memory and composition need
separate demonstrated sufficiency.
